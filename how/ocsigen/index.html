    Ocsigen framework

    Belenios uses the Ocsigen framework and its associated libraries (Eliom, Tyxml, Js_of_ocaml, Lwt) for the webserver.

    The web server itself is the binary ocsigenserver.

    The various component libraries of the ocsigen framework are:

    • tyxml
      Provides the syntax for working with XML (including html) in OCaml
    • eliom
      Provides libraries for server-client application programming
    • js_of_ocaml
      Converts OCaml to javascript
    • lwt
      Provides libraries for asynchronous programming

    Tyxml

    • syntax for an element which has one child uses ()
    • syntax for an element which may have more than one child uses the list syntax []

    Example: an html element has only one head element and only one body element; a head element has only one title element but also has other elements.

    Examples in utop:

    # require "tyxml";;
open Tyxml;;

let mypage = Html.(html (head (title (txt "My title"))[]) (body [div [txt "Hello world!"]]));;

    This produces:

    <html><head><title>My title</title></head><body><div>Hello world!</div></body></html>

    The example above over multiple lines for easier reading

    let mypage = Html.(
html
   (head
       (title (txt "My title"))
       []
   )
   (body
      [
         div [txt "Hello world!"]
      ]
   )
);;

    Eliom

    Services

    A key concept used by Eliom is that of a "service". Eliom registers services for web address paths. For example, the registered service for a path might define the page html content for that path.

    An example is the following:

    (* Define a module which inherits from the Eliom module App *)
module My_app = 
  Eliom_registration.App (
  struct
    let application_name = "eliom_minimal"
    let global_data_path = None
  end)

(* Define a service for the path "" - the home page - eg www.example.com *)
let main_service =
  Eliom_service.create
    ~path:(Eliom_service.Path [""])
    ~meth:(Eliom_service.Get Eliom_parameter.unit)
    ()

(* Define a service for the path 'page2' - eg www.example.com/path2 *)
let page_two_service = 
  Eliom_service.create
    ~path:(Eliom_service.Path ["page2"])
    ~meth:(Eliom_service.Get Eliom_parameter.unit)
    ()

(* Register main_service and the content to be returned *)
let () =
  My_app.register
    ~service:main_service
    (fun () () ->
       Lwt.return
         (Eliom_tools.F.html
            ~title:"Minimal eliom setup"
            ~css:[["css";"base.css"]]
             Eliom_content.Html.F.(
              body [
                h1 [txt "Welcome to a minimal Eliom setup"];
                div ~a:[a_id "div1"] [
                  p [txt "This is a paragraph of text"];
                  p [txt "This is a link to the "; Raw.a ~a:[a_href (Raw.uri_of_string "https://google.com")] [ txt "Google" ]; txt " search engine." ]; 
                  p [Raw.a ~a:[a_href (Raw.uri_of_string "page2")] [txt "page two"] ];
                ];
              ])))

(* Register page_two_service and the content to be returned *)
let () = 
  My_app.register
  ~service:page_two_service
  (fun () () ->
    Lwt.return
      (Eliom_tools.F.html
        ~title:"Page two"
        ~css:[["css";"base.css"]]
        Eliom_content.Html.F.(
          body [
            h1 [txt "This is page two"];
          ]
        )))

    Server / client

    A second important feature of eliom is its ability to provide server code, client code and code which is shared, in the same file. Client code is javascript provided by js_of_ocaml. The syntax directs whether code should be executed on the server, the client or is shared. 

    let%server, let%client, let%shared        (* For single definiions *)

[%%server ], [%%client ], [%%shared ]     (* For enclosed multiple defintions *)

[%client  ]                               (* Client code inside server code *)
